# MAX Mini App Test

Минимальное тестовое мини-приложение для MAX.

## Что проверяет

- открывается ли страница внутри MAX;
- загрузился ли официальный MAX Bridge;
- доступны ли `window.WebApp.platform`, `version`, `deviceName`;
- передаются ли данные пользователя через `initDataUnsafe`;
- работает ли обычный JavaScript-интерфейс.

## Структура

```text
max-miniapp-test/
├── index.html
├── style.css
└── app.js
```

Backend и API-токен для этого теста не нужны.

## Локальный запуск

Можно открыть `index.html` напрямую, но удобнее запустить локальный сервер:

```bash
python -m http.server 8080
```

После этого открыть:

```text
http://localhost:8080
```

В обычном браузере приложение покажет демо-режим. Данные MAX появятся только при запуске внутри MAX.

## Публикация через GitHub Pages

1. Создайте репозиторий.
2. Загрузите в корень `index.html`, `style.css`, `app.js`.
3. Откройте `Settings → Pages`.
4. В `Build and deployment` выберите `Deploy from a branch`.
5. Выберите ветку `main` и папку `/root`.
6. Дождитесь появления HTTPS-адреса.

Пример адреса:

```text
https://username.github.io/max-miniapp-test/
```

## Подключение в MAX

По текущим правилам MAX мини-приложение обязательно привязывается к чат-боту, но программировать самого бота не требуется.

1. Создайте пустого чат-бота в профиле MAX для бизнеса.
2. Откройте `Чат-боты → Перейти`.
3. Выберите нужного бота.
4. Откройте `Расширенные настройки → Настроить`.
5. Вставьте HTTPS URL опубликованного приложения.
6. Выберите текст кнопки открытия.
7. Сохраните настройки.
8. Откройте чат с ботом и нажмите кнопку запуска Mini App.

## Безопасность

`initDataUnsafe` удобно выводить только в тестовом проекте. В настоящем приложении доверять этим данным напрямую нельзя — строку `initData` нужно проверять на backend.

Не добавляйте токен бота в frontend, JavaScript или публичный GitHub-репозиторий.
