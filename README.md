# Тындекс ID — мастер-класс по фишингу

Интерактивная учебная демо для запуска как обычная страница или MAX Mini App.
Она показывает, что знакомый и «правильный» интерфейс сам по себе не гарантирует
безопасность: введённые в форму значения сразу становятся доступны коду страницы.

> Важно: вводите только вымышленные значения. Это демонстрационный проект, а не
> форма входа в настоящий сервис.

## Что внутри

- вкладка «Авторизация» с полями логина, пароля и одноразового кода;
- вкладка «Что увидит фишер» с отображением введённых значений;
- безопасный автозаполнитель демо-данными;
- очистка всех данных одной кнопкой;
- адаптивный интерфейс для телефона и десктопа;
- статические относительные пути, совместимые с GitHub Pages.

## Почему демо ничего не отправляет

- у проекта нет backend и API;
- значения хранятся только в JavaScript-объекте в памяти открытой вкладки;
- не используются `localStorage`, `sessionStorage`, cookies или аналитика;
- Content Security Policy задаёт `connect-src 'none'` и `form-action 'none'`,
  запрещая сетевую отправку из интерфейса и отправку HTML-формы;
- после обновления или закрытия страницы введённые значения исчезают.

Из-за строгой политики безопасности внешний MAX Bridge намеренно не загружается:
для этой демонстрации он не нужен. Страница при этом может открываться внутри MAX
как обычный статический Mini App.

## Локальный запуск

```powershell
python -m http.server 8080
```

Откройте `http://localhost:8080`.

## Публикация на GitHub Pages

1. Отправьте файлы в ветку `main` GitHub-репозитория.
2. Откройте `Settings → Pages`.
3. В `Build and deployment` выберите `Deploy from a branch`.
4. Укажите ветку `main` и каталог `/ (root)`.
5. Сохраните настройки и дождитесь HTTPS-адреса.

Все ссылки на CSS, JavaScript и изображения относительные, поэтому проект работает
как на корневом домене, так и по адресу вида
`https://username.github.io/repository-name/`.

## Сценарий мастер-класса

1. Покажите участникам знакомую форму и попросите назвать признаки «надёжности».
2. Нажмите «Подставить безопасные демо-данные» или введите вымышленные значения.
3. Перейдите на вторую вкладку или нажмите «Войти в Тындекс».
4. Обратите внимание: странице уже известны все значения, включая пароль и код.
5. Обсудите, почему дизайн, HTTPS и значок замка не подтверждают владельца сайта.
6. Завершите тремя проверками: адрес, источник ссылки, уместность запроса данных.
